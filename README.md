# Kittygram Foster

`Kittygram Foster` — учебный веб-проект на Django REST Framework и React.
Проект расширяет базовый `Kittygram` функционалом учета статуса владения
котом и договоров передержки.

## Назначение проекта

Система позволяет:
- регистрировать пользователей и выполнять авторизацию по токену;
- создавать карточки котов с именем, цветом, годом рождения, фото и достижениями;
- назначать коту статус владения: `home` или `foster`;
- создавать договоры передержки с датами начала и окончания;
- закрывать активный договор передержки;
- просматривать список котов, находящихся на передержке;
- работать с API через Swagger и ReDoc.

## Предметная область

В проекте используются следующие основные сущности:
- `Cat` — карточка кота;
- `Achievement` — достижение кота;
- `OwnershipStatus` — текущий статус владения котом;
- `FosterContract` — договор передержки.

## Реализованные бизнес-правила

В системе действуют следующие ограничения:
- у одного кота может быть только один статус владения;
- у одного кота может быть только один активный договор передержки;
- дата окончания договора не может быть раньше даты начала;
- нельзя перевести кота в домашний статус, пока активный договор не закрыт;
- договор передержки создается только для кота со статусом `foster`;
- изменять данные о статусе и договоре может только владелец кота.

## Локальный запуск проекта

1. Получить файлы проекта и перейти в корневой каталог:

```bash
cd kittygram_foster
```

2. Создать файл `.env` по образцу `.env.example`.

Пример содержимого `.env`:

```env
SECRET_KEY=temporary-dev-secret-key-change-me
DEBUG=True
ALLOWED_HOSTS=127.0.0.1,localhost,testserver
POSTGRES_DB=kittygram
POSTGRES_USER=kittygram_user
POSTGRES_PASSWORD=kittygram_password
DB_NAME=kittygram
DB_HOST=db
DB_PORT=5432
```

3. Собрать и запустить контейнеры:

```bash
docker compose up --build -d
```

4. Применить миграции:

```bash
docker compose exec backend python manage.py migrate
```

5. Собрать статические файлы и подготовить их для раздачи через `nginx`:

```bash
docker compose exec backend python manage.py collectstatic --no-input
docker compose exec backend cp -r /app/collected_static/. /backend_static/static/
```

6. При необходимости создать суперпользователя:

```bash
docker compose exec backend python manage.py createsuperuser
```

7. Проверить состояние контейнеров:

```bash
docker compose ps
```

## Авторизация в API

В проекте используется токен-аутентификация.

Получение токена:

```http
POST /api/token/login/
```

Пример тела запроса:

```json
{
  "username": "olga",
  "password": "olgapass"
}
```

После получения токена его необходимо передавать в заголовке:

```text
Authorization: Token <ваш_токен>
```

## Новые API-эндпоинты

### Статусы владения

- `GET /api/ownership-statuses/`
- `POST /api/ownership-statuses/`
- `PATCH /api/ownership-statuses/{id}/`

### Договоры передержки

- `GET /api/foster-contracts/`
- `POST /api/foster-contracts/`
- `PATCH /api/foster-contracts/{id}/`
- `POST /api/foster-contracts/{id}/close/`

### Список котов на передержке

- `GET /api/cats/foster/`

## Примеры запросов и ответов

### Назначение статуса владения

Запрос:

```json

  "cat": 1,
  "status": "foster"

```

## Работа с Postman

Для проверки API в проект добавлена коллекция `kittygram_foster_postman_collection_ready.json`.

Коллекция содержит готовые запросы и позволяет не вводить токен вручную для каждого эндпоинта.

Порядок работы:

1. Открыть `Postman`.
2. Нажать кнопку `Import`.
3. Выбрать файл `kittygram_foster_postman_collection_ready.json` из корня проекта.
4. В левой панели открыть импортированную коллекцию `Kittygram Foster API`.
5. Сначала выполнить запрос `1. Login`.
6. После успешного ответа токен автоматически сохранится в переменную коллекции `token`.
7. Далее можно выполнять остальные запросы без ручного копирования токена в заголовки.

Назначение основных запросов:
- `1. Login` — получение и автоматическое сохранение токена;
- `2. Get Foster Cats` — получение списка котов на передержке;
- `3. Create Ownership Status` — назначение коту статуса `foster`;
- `4. Create Foster Contract` — создание договора передержки;
- `5. Close Foster Contract` — закрытие ранее созданного договора.

Если требуется проверить создание и закрытие договора подряд, достаточно выполнить запросы в следующем порядке:
1. `1. Login`
2. `3. Create Ownership Status`
3. `4. Create Foster Contract`
4. `5. Close Foster Contract`

После запроса `4. Create Foster Contract` идентификатор договора автоматически сохраняется в переменную `contractId`, поэтому в следующем запросе его не нужно вводить вручную.
